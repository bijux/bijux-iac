# GitHub repository rulesets

This module owns the `main-branch-protection` ruleset for each of the twelve
repositories declared in the root inventory. It uses
`github_repository_ruleset.main[repository]` resource addresses and the committed
GitHub provider lock. The owner is restricted to `bijux`.

The ruleset targets the default branch with no exclusions or bypass actors.
It blocks deletion and force pushes, requires reviewed pull-request integration
under the existing owner self-signoff model, resolves review conversations,
and enforces strict required checks bound to their GitHub Actions producer.
The zero approving-review count is intentional; the PR approval policy check
implements that review model.

## Inputs and outputs

| Input | Source |
| --- | --- |
| `ruleset_repositories` | Exact validated family rendered from `inventory/repositories.json` |
| `ruleset_required_status_checks` | Common floor plus applicable owned product gates |
| `ruleset_required_approving_review_count` | Existing owner review model |
| `github_owner` | Fixed `bijux` owner |
| `github_token` | Protected environment credential; sensitive and never committed |

`ruleset_protected_main_branches` reports the managed ruleset IDs.
The committed `terraform.auto.tfvars.json` is generated by
`python3 -B -m scripts.terraform.render --write`; `make tfvars-check` detects drift.

## Operation

Run commands from the repository root. `make terraform-format-check` checks
this authored module. `make terraform-validate` copies the governed inputs and
provider lock into `artifacts/terraform/module`, initializes with the lock
read-only, and validates that copy. Runtime state and plans remain in artifacts.

The execution boundary validates inventory and current accepted main, discovers
all live rulesets authoritatively, and imports their IDs before planning.
Discovery failure or ambiguity stops the operation. Application consumes the
saved plan for exactly the validated input digests and audits the full family.
No persistent state backend or independent settings-write route is provided.
See the [root operating guide](../../../README.md) for commands, credentials,
receipts, and the accepted-main application boundary.
